# K971 — The count crux, reduced to one checkable claim

**Not a derivation — an audit sharpening.** K970 named the count's open crux as "reconcile the F86 strata (3, bounded) with the F340/§118 singleton rung tower (infinite)." This note reduces that to ONE load-bearing claim, so Lyra's corpus run has a precise target and my §119 audit has a precise object. I assert nothing about whether the claim holds — that is Lyra's Bergman/localization computation.

## The three corpus pieces, assembled
- **Cal §118 (F340 side):** the Di spinor minrep has an **infinite** SO(5)-harmonic rung tower — F338 records the tower {1,5,14,30,...} = SO(5)-harmonic degrees {0,1,2,3,...}. Nothing in the *representation* truncates it.
- **F86 (strata side):** D_IV⁵ has exactly **3 support-dimension strata** {n_C=5 bulk / rank=2 Cartan slice / 0 Shilov point} — the inverted pyramid, rank+1 = 3.
- **K945 route (ii):** the **matryoshka** (the nested-subdomain chain D_IV⁵ ⊃ D_IV² ⊃ point) **terminates** at the Shilov point — exactly rank+1 = 3 nested levels.

## ★ The reconciliation candidate (the claim to test)
The rung tower is infinite as a *representation*, but a rung is a *physical generation* only if it has boundary support — and boundary support lives on the strata. So the candidate mechanism:

> **Rung k localizes on matryoshka level k** (k=0 bulk → electron, k=1 Cartan slice → muon, k=2 Shilov point → tau), and the matryoshka terminates at level 2 (K945 route ii). Rung k≥3 exists as a representation state but has **no 4th nested stratum to localize on** → not a physical generation.

If this holds, the infinite rung tower is truncated to **exactly 3 boundary-supported rungs** — and Cal's §118 "nothing truncates the tower" is answered: the *representation* isn't truncated, the *normalizable/physical* generations are, by strata exhaustion. This makes K945's three routes and §118 **one consistent picture**, not a conflict.

## ★ The forced-vs-match test (Cal §119 bar — the audit object)
The load-bearing claim is the **rung↔level correspondence**, and it must be *forced*, not fit:
- **FORCED (exactly-3 closes) IF:** rung k's Bergman support (F483/F84 localization; F338 harmonic degree) provably sits on matryoshka level k — i.e. the SO(5)-harmonic degree-k mode is normalizable only on the k-th nested subdomain — with **the identical mechanism giving 4 levels on E7** (rank 3 → rank+1 = 4). Then the strata *exhaust* the physical rungs and 3 is derived.
- **MATCH (stays REDUCED) IF:** the localization does NOT track the matryoshka — if rungs k≥3 are equally normalizable, or the degree↔level map is imposed rather than derived. Then "3 strata → 3 generations" is the K944 count-match in new clothes, and the count stays REDUCED.

**The single computation that decides it (Lyra, corpus-run):** the Bergman localization of the Di-singleton rungs (F483 eigenvalue frame + F84/F85 kernel + F338 rung degrees) against the matryoshka nesting (F666: strata = sub-domains with genera {n_C, N_c, 0}). Does degree-k support = nested-level-k? Run F483/F666, don't re-derive.

## What this does NOT claim
- It does not claim the correspondence holds — that is Lyra's computation.
- It does not promote the count — the count stays **REDUCED / Identified-Conditional** until the correspondence is shown forced + E7-uniform.
- It does not replace K945 — it *uses* K945 route (ii) as the termination and asks whether that termination truncates the §118 rungs.

**Net:** the count crux is now one checkable claim (rung k ↔ matryoshka level k) with a forced-vs-match test and a named computation (F483/F666 localization vs nesting). That is the audit target; the run is Lyra's.
