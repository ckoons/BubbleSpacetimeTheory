# K1213 — consistency sweep: clean; one clarifying pin (scalar genus 5 vs fermion weight 7)

After a night with three self-corrections, I swept the corpus for stale live assertions of the superseded claims. **Clean — the corrections propagated.**

## Sweep results
1. **"genus = n_C = 5" everywhere is correct, not stale.** That's the *scalar* Bergman-kernel genus, which genuinely is 5 (K1201 confirmed the bare scalar exponent). K1200's error was *conflating* the scalar genus with the fermion mode weight — not the value 5 itself. Those files stand.
2. **Toy 5073** (booleans + wrong "9.84 gap") has no self-marker, but **toy 5074 + K1201 explicitly supersede it** (5074's filename states it owns the wrong-gap ceremony) — the never-delete-stamp-superseded discipline is satisfied.

## The one clarifying pin (the conflation I fell into)
Worth a permanent statement so nobody re-trips:
- **The geometric / scalar Bergman-kernel genus of D_IV⁵ is n_C = 5** (kernel K ~ N⁻ⁿ, n=5; FK multiplicity p = (r−1)a + b + 2 = 5 for type IV).
- **The fermion discrete-series mode weight — the up-Yukawa overlap exponent y = n_C^(−weight) — is g = 7** (the spinor one rung above the C_2=6 scalar; Lyra's mechanism, K1201).

**These are different objects.** K1200 used the scalar genus 5 where the fermion weight 7 belongs, and missed the up-quark's 5⁻⁷; K1201 corrected it. So when a note says "genus," disambiguate: **scalar Bergman genus = 5, fermion mode weight = 7.** Don't use 5 for the fermion overlap exponent, and don't "fix" the legitimate scalar-genus-5 statements to 7.

## Why it matters
I made exactly this conflation tonight, and it's an easy one — both are BST integers, both are "genus"-adjacent in different notes. A future CI could either repeat my miss (use 5 for the fermion weight) or wrongly "correct" the scalar-genus-5 notes to 7. This pin prevents both.
