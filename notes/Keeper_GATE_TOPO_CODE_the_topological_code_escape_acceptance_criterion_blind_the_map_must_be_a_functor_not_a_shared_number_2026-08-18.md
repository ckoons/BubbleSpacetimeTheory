# GATE-TOPO-CODE — the escape, caged before it computes

K1694 resolved Block C to a fork — `{N_c=3 forced}` XOR `{proton exactly stable}` — with **one escape**: a topological error-correcting code where the topology *is* the repair, which would dissolve the fork and give the whole prize (`N_c=3` forced, proton stable, Five-Absence kept, `n_C=5` fully intrinsic). It's the biggest claim the program could make, so I pin its acceptance criterion **blind**.

## Acceptance — four conditions, all required
1. **A genuine map, not a shared number.** Exhibit an explicit functor from the *winding* (topological — π₁/knot, T1930/T1294) to the *code* (combinatorial — the `[3,1,3]` stabilizers). "Winding-count = 3 = code-length = 3" is the shared-number trap — the *exact* ill-typed crossing that failed in K1686. Check the types first; a number-match is an automatic fail.
2. **The topology performs the repair.** The correction must be realized *topologically* (Kitaev — logical operators = non-contractible cycles, local stabilizers), not a symbol-by-symbol majority vote with a failure rate. That's what buys exact stability with no finite-`τ_p` price. A rate-process "correction" fails — it brings back the Five-Absence collision.
3. **No decay channel reintroduced.** Verify exact stability genuinely survives — no residual logical-error channel giving a finite proton lifetime. The Five-Absence "no proton decay" must stay intact.
4. **`N_c=3` still target-innocent.** The length-3 must come from the coding side (Singleton + minimality/P2b), *not* be read back from `winding = n−2` (circular). The map sends the forced length to the winding, not the reverse.

## Ruling logic
All four → **YES**: `N_c=3` forced + exact stability + Five-Absence + five intrinsic — the prize, and Casey was right from the start. Any failure (shared-number-not-functor / rate-process correction / reintroduced decay / circular length) → the **fork stands**, `n_C=5` = input, BST keeps exact stability and the flagship.

**Guard:** this is the maximal-seduction claim (Cal #27 at its peak). The K1686 barrier is the *default* expectation; a genuine knot→code functor is the hard, rare thing. Don't let "both give 3" or a suggestive analogy stand in for the map.
