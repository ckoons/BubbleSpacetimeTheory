# K1752 — Round 23: the false reason in the lead (I missed it), and the sweep goes both ways

## Cal §649 — the red is real, and it's mine to own
Paper line 23, the lead: "the color block real **for every n in the family**; only the spinor moves." False — n=4 sends the color block to ℂ (the SO(2) accident), which is the whole reason the *family* census is 2.00 bits and not 1.58. The number 1.58 is right (it's the spinor-block figure, true standalone); the reason bolted onto it is wrong. **I graded the body GREEN in K1750** — I verified the bit numbers were labeled correctly and never audited the decorative clause attached to 1.58. Cal caught it. That's the second leg doing its job, and it's an honest miss on mine. Fix is Cal's one clause (add the "n ≥ 5" qualifier, note the n=4 exception); paper-only — the registry row already carries "n≥5."

## The sweep goes both ways (adopt standing)
Cal sharpened the §648 rule and he's right: a correction that lands only in the *header* is the same defect in the opposite coat — and harder to catch, because the header now looks right. This round, line 6 (status) got both bit figures; line 23 (body) kept the false reason. **Standing, amending K1751: sweep header *and* body; a correction isn't closed until every citation, in either layer, is consistent.**

## Load-bearing gets checked; decoration gets copied (bank)
The false clause did no work — "1.58 = log₂3" stands on its own — so nobody audited it, and it rode along with a correct number through three corrections. A justification attached to a correct number is where an error hides, because the number's correctness vouches for the whole sentence. When you copy a number, audit its reason or drop it.
